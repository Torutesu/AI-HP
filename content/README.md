# マガジン制作パイプライン

記事を「AIスロップ」にせず、有益・オリジナル・人間のための内容にするための
制作フロー。Googleが見るのは「AIが書いたか」ではなく「役に立つ・オリジナル・
人のために書かれているか」。各ステップに品質ゲートを置いて、それを担保する。

## ファイル

| ファイル | 役割 | 対応ステップ |
| --- | --- | --- |
| `keyword-backlog.md` | 記事のキーワードと検索意図の一覧。ここからしか着手しない | ①② |
| `product-definition.md` | 自社サービスの「できること／できないこと」。事実性の基準 | ③ |
| `quality-checklist.md` | 公開前の採点ゲート（合格ライン85点） | ⑥ |
| `magazine-thumbnails.md` | 本文連動サムネイルの生成・差分確認 | ④⑥⑦ |
| （記事本体）`../lib/magazine.ts` | 公開記事のデータ（本文・要点・FAQ・関連） | ④ |
| （編集方針）`/editorial-policy/` | 一次情報主義・出典・時点明記・訂正 | 全体 |

## 7ステップ

1. **キーワードリサーチ** — `keyword-backlog.md` から着手。近いトピックを勝手に
   拾わない。バックログが残り3本を切ったら補充する。
2. **検索意図** — 書く前に意図を1つ確定（比較/ハウツー/定義/購入ガイド/
   トラブル対応/リスト）。
3. **プロダクト検証** — サービスへの言及は `product-definition.md` と照合。
   「ない機能」を書かない。
4. **記事構成** — 固定構造で書く：キーワードを含むタイトル / 冒頭ショート
   アンサー（要点）/ 見出し / FAQ / 内部リンク / プロダクト言及 / CTA。
5. **アンチスロップ（2パス）** — 誇張語・空虚な文句・根拠なき主張を削り、
   文頭の反復・弱い接続・長すぎる段落・ダッシュ「——」の多用を直す。
6. **品質スコア＋差し戻し** — `quality-checklist.md` で採点。85点未満は
   ステップ4へ差し戻す。特に「人間らしさ」と「事実性」を重視。
7. **公開** — サムネイルブリーフ更新 → ビルド → デプロイ（本番ドメイン `ai-hp.pages.dev`）→ 反映確認。
   新規URLはGoogle Search Consoleでインデックス申請。

## 記事データの構造（`lib/magazine.ts`）

`Article` 型の主なフィールド：

- `summary` — 冒頭ショートアンサー（結論先出し）。ステップ4/LLMO。
- `body[]` — `## 見出し` / `- 箇条書き` / `※注記` / 段落 / インラインリンク
  `[ラベル](/magazine/slug)`。
- `faq[]` — 記事末FAQ＋FAQPage構造化データ。
- `related[]` — トピッククラスターの関連記事slug（カテゴリ横断可）。
